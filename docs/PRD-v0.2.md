## 1. Where we are

v0.1 shipped its trust core and most economics/memory: 4-family evidence gate with
command re-runs, lock-before-work ledger, scope-lock rejection, official-rails meter
ledger with pacing, history-based bench, quiet hours, sweep evidence snapshots,
`proof --verify`, `watch --replay`, 12 real commands, zero deps, 38 tests.

## 2. What v0.2 is for: beyond parity

Parity = matching the brochure. Beyond parity = the harness improving *itself* with
checkable evidence, on this machine, without a human in the loop. Each iteration must
leave the repo greener: tests passing, claims true, one measurable number moved.

## 3. Requirements (each is one self-run iteration)

Priorities: all are P1 unless marked. Each iteration = `cadre parity --ref docs/PRD-v0.2.md`
with a brief naming its item, gate must pass or the item reverts.

- **B1 — §8 metrics instrumented:** `cadre metrics` sub-command: false-DONE rate from
  `proof --verify` history, median bundle inspect time (log timestamps), sweep-recovery
  rate, metered-burn per passed run. Real numbers from the ledger only; "—" when absent.
- **B2 — standalone loop (v0.1 §6.2 P1):** `go --local` runs plan/build/critique/verify
  without ax: builder = user lanes (command kind) or apertus; ax becomes just another adapter.
- **B3 — adapter breadth:** Gemini CLI detection in scan.js + a documented generic-CLI
  template lane (`examples/lanes/generic-cli.json` with `{brief}` command template).
- **B4 — map warmth:** map index cached under $CADRE_HOME/maps with mtime invalidation;
  `go`/`plan` consult hot zones as router hints (files recently touched rank their lanes up).
- **B5 — frugal pipes:** builder output compressed (dedup blank lines, cap at N KB with
  head+tail) before entering run.log and before any context re-read. Log the bytes saved.
- **B6 — parity ledger:** each parity run appends a structured ledger entry
  (`parity-ledger.jsonl`): target, ref, gaps claimed closed, gate verdict, citations.
  `cadre parity --ledger` renders it.
- **B7 — resume honesty (v0.1 §6.5):** sweep --resume emits a resume plan artifact:
  what was done (evidence kept), what remains (steps not yet logged), re-brief command.
- **B8 — gate hardening:** verifier independence — a run cannot pass with evidence only
  its builder produced; require ≥1 command evidence from a non-builder role (verifier/
  critic), enforced in gate.js with a test.
- **B9 — failure-mode tests:** kill -9 a run mid-loop (spawn + kill in test), assert
  sweep finds it, snapshot files, retire files state, ledger consistent. Same for
  quiet-hours refusal and scope-creep rejection at the CLI level (spawn, not unit).
- **B10 — self-doc:` docs/BECYOND-PARITY.md` auto-generated table: iteration → item →
  commit → gate verdict → metric moved. Generated by `cadre metrics --report`, so the
  doc can't drift from the ledger.

## 4. Exit criteria

All ten items land with the gate passing, tests ≥ 50, zero invented metrics, and
BECYOND-PARITY.md generated (not hand-written). A rejected iteration must revert or
re-brief — never silently kept.
